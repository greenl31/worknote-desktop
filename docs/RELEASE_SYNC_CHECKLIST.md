# Worknote 上传发布检查清单

本文件是 Worknote 的长期发布规则。目标是让每次私有仓库同步、公开仓库同步、macOS/Windows 打包和 GitHub Release 都可重复、可核对、可追溯。

## 触发用语与范围

- 用户说“上传发布”或“发布同步”：执行完整流程，包括私有仓库同步、公开仓库安全净化、双平台构建、更新说明、精确提交、推送、标签和 GitHub Release。
- 用户说“同步私有”：只处理私有仓库，不创建公开发行包。
- 用户说“同步公开”：只处理已经通过安全审核的公开仓库和公开发行。
- 用户只说“同步”且没有另行限制时：按完整流程准备并核对私有版与公开版；任何检查失败立即停止，不带病提交或发布。
- 发布、推送和远端 Release 必须来自用户当轮明确指令；检查清单本身不构成自动发布授权。

## 一、发布身份

- [ ] 明确本次版本号、发布日期、发布范围和目标仓库。
- [ ] `Cargo.toml`、`Cargo.lock`、`tauri.conf.json`、Git 标签和 Release 名称的版本一致。
- [ ] 确认应用 identifier 未被意外修改；如必须修改，先提供数据迁移方案。
- [ ] 明确本次是测试包、未签名公开包，还是正式签名/公证包，不混用口径。
- [ ] 列出本次允许修改、暂存和提交的精确文件；不使用 `git add .`。

## 二、Git 与源码边界

- [ ] 在每个具体项目根目录执行 `git rev-parse --show-toplevel` 和 `git status --short`。
- [ ] Git 根目录与目标项目完全一致，不在用户目录、桌面或项目上级目录操作。
- [ ] 记录所有已有改动；未知改动、无关改动或无法解释的二进制文件必须先停止。
- [ ] 私有仓库与公开仓库分别检查，禁止直接把私有工作目录整体复制进公开仓库。
- [ ] 公开发行必须从公开仓库的全新干净检出构建，不从含真实用户数据的开发目录打包。
- [ ] 提交前检查 staged diff；提交后检查工作区和提交文件清单。

## 三、安全与隐私洁净审核

### 禁止进入公开源码、提交和安装包的内容

- [ ] API Key、Token、Cookie、Session、密码、OAuth Client Secret、Webhook 密钥和授权头。
- [ ] `.env`、`.env.*`、`*.pem`、`*.key`、`*.p12`、证书私钥、SSH 配置和签名凭据。
- [ ] SQLite/数据库文件、真实任务内容、JSON 导出、备份、日志、崩溃报告、缓存和临时文件。
- [ ] 个人姓名、私人邮箱、手机号、账号、用户目录名、设备名、序列号和可识别身份的截图。
- [ ] `/Users/<name>/...`、`C:\Users\<name>\...` 等个人电脑绝对路径。
- [ ] 内网 IP、局域网主机名、内部域名、代理地址、私有 API、回调地址、调试端口和内部链路信息。
- [ ] 构建目录、开发数据库、测试导出、未审查的压缩包和其他机器生成产物。

### 必须执行的检查

- [ ] 检查敏感文件名和 `.gitignore` 覆盖范围。
- [ ] 扫描常见密钥前缀、`token`、`secret`、`password`、`authorization`、私钥头和高熵可疑字符串。
- [ ] 扫描 macOS、Windows 和 Linux 的个人绝对路径、用户名、邮箱、手机号、IP 和主机名。
- [ ] 审核所有 URL：只保留明确需要的公开项目链接和官方文档链接。
- [ ] 检查 Git 当前历史中是否曾提交敏感内容；发现后不能只删除当前文件，必须先处理历史泄漏和密钥轮换。
- [ ] 解包最终安装包再次扫描，确认资源中没有数据库、备份、日志、源地图、调试配置或本机路径。
- [ ] 确认程序默认不上传任务、不含遥测、不连接未声明服务；如以后增加联网能力，必须更新隐私说明。
- [ ] 安全结论必须写“发现了什么、检查了什么、未能证明什么”，不得只写“应该没问题”。

## 四、代码与依赖审核

- [ ] JavaScript 语法检查通过，HTML/CSS 无明显错误和资源丢失。
- [ ] `cargo fmt --check` 通过。
- [ ] `cargo clippy --all-targets --all-features -- -D warnings` 通过。
- [ ] `cargo test` 全部通过。
- [ ] `cargo tauri build` 通过。
- [ ] 审核 `Cargo.lock` 的新增或升级依赖；没有来源不明、未使用或重复依赖。
- [ ] 审核 GitHub Actions 的第三方 Action、权限和触发条件；发布权限保持最小化。
- [ ] 检查无用代码、未引用资源、调试输出、测试后门和临时开关。

## 五、功能回归

- [ ] 新增、完成、取消完成、编辑、删除和清空已完成正常。
- [ ] 优先、紧急、重要可独立及组合选择；排序稳定。
- [ ] 日期选择、今日/明日/待安排、创建时间和最近记录正常。
- [ ] 快速记录在 0 条任务时默认展开，在 1 条及以上任务时默认收起，新增成功后收起。
- [ ] 顶部工作区滚动时保持置顶，任务列表可正常滚动且不被遮挡。
- [ ] `中/EN` 可即时切换并记住选择；中文和英文均无遗漏、截断、重叠和横向溢出。
- [ ] 普通窗口、贴边小窗、左右吸附、收起胶囊、托盘和重启持久化正常。
- [ ] SQLite 数据路径和既有用户数据兼容；升级不删除、不重置、不迁移到新 identifier。
- [ ] JSON 导出和每日备份正常，且导出文件不会进入 Git 或安装包。

## 六、双平台发行包

### macOS

- [ ] 在干净公开仓库上构建 `.app` 和 `.dmg`。
- [ ] 检查应用名称、版本、identifier、图标、最低系统版本和架构。
- [ ] 执行 `codesign --verify --deep --strict`。
- [ ] 有 Apple Developer 账号时执行 Developer ID 签名、公证和 stapling，并验证 Gatekeeper。
- [ ] 没有正式签名/公证时，Release 必须明确写明 Gatekeeper 操作和风险，不得声称“已公证”。
- [ ] 在新用户环境测试 DMG 拖入 Applications、首次启动、升级安装和卸载后数据保留。

### Windows

- [ ] 由 Windows 环境或受控 GitHub Actions 构建 NSIS `setup.exe`；不在 macOS 上伪称完成 Windows 实机包。
- [ ] 检查应用名称、版本、identifier、图标、安装目录、开始菜单和卸载项。
- [ ] 有代码签名证书时签名并验证；未签名时在 Release 明确说明 SmartScreen 提示。
- [ ] 在 Windows 10/11 测试安装、首次启动、升级、卸载和数据保留。

### 产物共同要求

- [ ] 记录每个发行文件的文件名、大小和 SHA-256。
- [ ] 安装包只包含当前版本产物；不混入旧包、调试包、数据库和本机配置。
- [ ] 从 GitHub Release 实际下载一次，再核对哈希和启动结果。

## 七、更新说明

每次发布创建 `docs/releases/Vx.y.z.md`，至少包含：

- 版本号、完成时间、Git commit 和 Git tag。
- 中文与英文更新摘要。
- 新功能、修复、行为变化和兼容性说明。
- 数据库/配置是否迁移，以及回滚影响。
- macOS/Windows 安装说明、签名/公证状态和已知限制。
- 测试命令与结果、人工验证项和未验证项。
- 安全洁净审核范围、结果和安装包 SHA-256。
- 回滚版本和回滚方法。

## 八、发布执行与发布后检查

- [ ] README、隐私说明、许可证、截图、下载说明和系统要求与当前版本一致。
- [ ] 私有仓库先保存完整开发版本；公开仓库只同步经过审核的公开内容。
- [ ] 精确暂存允许文件，复核 staged diff 后再提交。
- [ ] 推送正确分支；标签只指向已验证的发布提交。
- [ ] GitHub Actions 检查和双平台构建全部成功。
- [ ] GitHub Release 的标题、正文、附件和版本一致，没有重复或过期安装包。
- [ ] 发布后完成一次 macOS 和 Windows 下载/安装冒烟测试。
- [ ] 将最终 commit、tag、Release 地址、产物哈希和完成时间写回版本记录。

## 九、停止条件

出现以下任一情况必须停止发布：

- Git 根目录错误、存在未知改动或提交范围不清。
- 发现密钥、个人信息、真实任务数据、本机路径、内部网络或链路信息。
- 测试、构建、签名验证、安装测试或哈希核对失败。
- 版本号、identifier、标签、Release 或安装包不一致。
- 无法证明公开包来自干净公开仓库。
- macOS/Windows 其中一端未验证，却准备宣称“双平台已完成”。

## 完成口径

只有全部适用项通过，并留下版本记录和可复核证据，才可报告“上传发布完成”。本地构建通过不等于 GitHub 已发布，未签名不等于已签名，自动化构建通过不等于 Windows/macOS 实机验收通过。
